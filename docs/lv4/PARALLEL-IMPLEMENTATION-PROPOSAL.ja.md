> **更新**：利用者の指示でM1を実行し、非GUI受入を完了してA3前で停止した。[実績](M1-COMPLETION.ja.md)を優先する。以下の「未指示」「未開始」は会話当時の初期案の記録。

**後続の具体計画**：[M1実行計画](M1-EXECUTION-PLAN.ja.md)／[12ジョブの担当カード](M1-DISPATCH-PACK.ja.md)。4→最大6並列、契約・依存・単独所有・終了条件を具体化した。以下は会話時点の初期案として残す。実装はまだ開始していない。

状態：**会話で検討した運用案の保存。実装の再開・M1の採用・ジョブの起動は未指示。** 2026-11-08のGitHub反映は現状の保存に限る。

Codex等が計画・統合を管理し、OpenCode Go経由のDeepSeekへ独立した実装を並行して任せる案。速さは担当数だけでは決まらず、境界・入力・終了条件を先に揃える必要がある。Folioでの実際の短縮率は未計測なので、人時の見積りをそのまま並列数で割らない。

| 担当 | 責任 | 最初のM1を採用した場合の候補 |
|---|---|---|
| Codex（統合担当） | 要件・I/O・安全条件の固定、共通ファイルの所有、差分レビュー、統合、最終検証・停止判定 | A0、A1の安全性境界、共有型・IPC・保存形式の確定 |
| Sol XHigh | 独立した設計・安全性レビューと統合後レビュー | 誤適用、別予約の消去、取り出し・復元時の原本変更、添付不足、結果不明の扱い |
| DeepSeek 2〜3担当 | 合意済みの小さい範囲の実装または試験案。担当外の変更は統合担当へ戻す | 保全一覧・書出し、別領域へのコピー復元、独立した失敗試験に分割できるかを確認 |

上の分割は仮案。書出し形式や復元の入口が未確定のまま、依存する仕事を同時に開始しない。`store.ts`、`main/index.ts`、`App.tsx`、共有型等を複数担当で同時編集せず、共通部分は統合担当に集める。

各担当へ、固定した入力スナップショット、編集可能なファイル、I/O、守る不変条件、試験、停止条件を渡す。現状は未コミット差分が大きいため、HEADだけからworktreeを作ると実装済み部分が欠ける。**未コミット・未追跡のファイルも含めた同一スナップショット**から分けるか、今回の保存コミットを基点にする。成果物は差分・実行した試験・ログ・未確認点を揃え、担当の完了報告だけで統合済みとは扱わない。

最初は小さい1波で実装・待機・レビュー・統合に要した時間を測り、次の波の担当数を調整する。M1を選ぶ場合の範囲はA0〜A2だけで、条件を満たしたら停止。GUI・Electron・実データの操作やA3以降への拡張は含まない。

会話時のローカル確認はOpenCode 1.18.30と、モデル一覧の `opencode-go/deepseek-v4.1-flash`、`opencode-go/deepseek-v4-pro`。これは保存時点の観測であり、次回の利用可否や速度・料金の保証ではない。公式の[Agents](https://opencode.ai/docs/agents/)と[Go](https://opencode.ai/docs/console/go/)を参照したが、ローカルV1と公式V2の設定差を確認してから利用する。
