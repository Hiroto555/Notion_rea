# R6 公開チェックポイント

旧DBの選択移行、列追加・型変更、強制終了後の入力復旧を、行ページ編集・DB作成・ビュー設定の保存と統合しました。

## できること

- 新DB・行を作成し、行ページの本文・タイトル・5型のプロパティを編集。表、サイド表示、全画面で保存と再起動を確認。
- 独立ビュー、AND/ORフィルター、複数の並べ替え、グループ、表示設定を保存。
- 旧DBを対象指定で移行。SQLite・添付のコピーを検証し、元JSONと履歴を保持。処理と結果記録を同じトランザクションで確定。
- テキスト・数値・チェックボックス・日付・セレクトの列追加、IDを保つ名前変更、変換可能な型変更。変換不能値や依存フィルターは理由を表示して中止。
- 入力と操作IDを復旧用ファイルへ保存。強制終了後は結果照会で保存済みの入力と後続入力を分け、本文・プロパティ・ビュー設定・入力途中の数値を復旧。
- 原本の版が変わった場合は原本を上書きせず、明示的に別ページへ復旧。結果不明は同じIDで照会し、壊れた／別ワークスペースの復旧ファイルは上書きしない。

## 再現

READMEのセットアップ後、`npm run build`、`npm test -- --maxWorkers=1 --no-file-parallelism`、`npm run test:e2e -- --workers=1 --retries=0` の順に実行してください。E2EにはGUIセッションとPlaywright Chromiumが必要です。実データとは別の保存先を使ってください。

合成デモはリポジトリのルートで `node scripts/r6-demo.mjs --prepare-only`、`node scripts/r6-demo-exercise.mjs` と実行すると `output/r6-demo` に作成されます。既に操作したデモは `node scripts/r6-demo.mjs` で再度開けます。実行済みのデモにexerciseを重ねることは拒否します。

## 残っている範囲

実ユーザーデータの移行、本番反映、起動時の自動移行、電源断・任意の外部書き込みへの保証、添付と履歴まで含む全体復元UIは未完了です。復旧用保存の応答前の入力、未送信の作成・列設定フォームは復旧保証に含みません。結果不明な元操作は自動再送しません。Relation/Rollup/Formula、同期・共同編集、配布署名・公証、物理日本語IMEやライブNotion比較も別の範囲です。

## GitHub公開の方法

GitHubの既存master `bd0f1e753258b8f29c3a436753f3bad9a1f84b16` を親に、ローカルR6の検証済みスナップショットを載せています。独立したH0/R4–R6のローカル履歴をGitHubの履歴と混同していません。既存公開済みの検証資料も保持しています。

公開用コピーだけで個人のローカル絶対パスを置換しました。資料中の `<workspace-root>` と `<home>` はローカル証拠の所在を示すプレースホルダーです。原本の作業場所、ローカルDB・添付・バックアップ・キャッシュ・ビルド出力は公開対象に含めません。過去に公開済みのGit履歴を書き換えたという意味ではありません。
