## 今回の実装

- 保存の操作ID・変更元revision・確認結果を保ち、再試行で重複適用や古い入力の上書きを防ぐ。
- 保存記録、DB、添付、バックアップの使用量と増減を手動計測し、上限と退避先を設定できる。
- 古いバックアップは使用中・最新世代の保護条件を再確認して外部へ退避する。台帳外ファイルは既存の添付URLが届く可能性のあるものを保全する。
- 起動時に書込み・移行前コピーの容量を確認し、既存の対応DBは容量不足時にも読み取り専用でページの閲覧と原本救出を利用できる。
- 起動前の旧ワークスペース取込みは、退避用と作業用の両方のコピー容量を事前確認し、DBと添付の内容を検証する。
- 移行前のスキーマ退避先は新たに作成・検証して公開する。古い退避ファイルを誤って再利用しない。
- アプリを起動できない場合にも、明示したワークスペースから診断用のDB・添付・復旧記録を救出できる。

## 起動できないワークスペースの救出

Folioを終了した状態で、リポジトリのルートから実行する。

```sh
npm ci
npm run folio:rescue -- --help
npm run folio:rescue -- --workspace /path/to/workspace --destination /path/to/exports --workspace-closed
```

ワークスペースと出力先は既存ディレクトリを指定する。出力先にはワークスペース外の空き容量のあるフォルダーを指定する。診断用の救出結果は専用形式で保存する。対象のPage JSONが壊れていても原文を保全し、将来の修復・調査に使える。CLIは対象の終了を明示確認し、救出中の変更も検出する。外部プロセスによる同時変更の完全な排除には、利用者による終了確認が必要。
