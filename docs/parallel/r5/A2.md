# R5 A2 — parent-controlled database settings UI

Base: `23f47c9ccd24376174bac170a43f5a794377d1a5`; worktree `views`, branch `codex/r5-views`.

## Implemented components

`DatabaseSettingsPanel` renders the parent's `DatabaseSettings` overlay and emits semantic `SettingsIntent` commands immediately on input. It owns no persisted drafts, save queues, revisions or retries.

- Tabs and keyboard Left/Right/Home/End selection; create by view type; rename; duplicate; move left/right; delete while preserving at least one view; change table/board/calendar/gallery type.
- Text search; existing typed/nested FilterBuilder; multiple sort fields and directions; grouping property and direction.
- pending/saving/saved/conflict/unknown/blocked/error/loading states. Conflict/unknown/error/blocked/loading disable settings controls. Unknown only offers result lookup through `onResolve`.
- View names follow the actual 200-character persisted schema. Duplicating a maximum-length name keeps its copy suffix within that limit.

`DatabasePresentation`'s read-only renderer accepts `controlledViewId`, `hideNavigation`, and optional `onSelectView`. A0 can use the parent-controlled active view to drive the existing board/gallery/calendar renderers without mounting the legacy editing writer. Omitting these props preserves its existing local read-only navigation. The old editable writer is untouched.

## UI contract

```ts
DatabaseSettingsPanel({
  settings,
  onIntent,
  status,
  error?,
  onResolve?,
  filterInputTexts?: Record<viewId, Record<filterId, string>>,
  onFilterInputTextChange?: (viewId, filterId, text) => void,
})
```

The outer App binds the database identity and edit session. Every patch captures only the affected fields of the displayed view as its base. New and copied views are fully prepared once; their view/filter/sort IDs are present in the submitted intent. Copy carries the observed source view as well.

FilterBuilder adds backward-compatible `inputTexts` and `onInputTextChange(filterId, text)` props. Numeric filters reuse PropertyField's raw text control: incomplete `-` / `1e` remains in the parent; complete finite values send the typed filter value, and deliberate clearing becomes the filter's empty string. Parent exit/reload guards should only consider currently existing numeric filter nodes with an operator needing a value. Deleted views/conditions or changed property types must not leave orphan raw keys blocking exit.

## Static integration review follow-up

Found and fixed a mismatch when a filter condition changes its target property.
The condition retains its ID while its typed value resets to empty, so the
parent's raw numeric text must reset in the same event. Otherwise number `12`
→ text target → number target displays `12` while the saved predicate is empty;
an incomplete `-` can also incorrectly reactivate the exit guard. FilterBuilder
now synchronizes the raw reset immediately, before emitting the typed change.

`git diff --check`: PASS. Runtime regression (numeric value → change target →
return to numeric target; repeat with incomplete numeric input): NOT_RUN here;
requested from the integrated QA lane.

The integrated checkbox-filter timeout also had a concrete serialization
cause: changing a condition target to checkbox emitted an own `value: undefined`
key. Store JSON removes that key; the exact settings ACK comparison then rejects
the otherwise-applied result and leaves settings in unknown state. Target changes
now always reset to `value: ""`, which no-value operators ignore and JSON retains.
The operator-only change path patches only `operator` and introduces no undefined
value. Existing newly-created checkbox conditions omit the optional key entirely.
The existing integrated typed-filter E2E covers this failure; rerun is owned by A0.

### Boundaries reviewed without another confirmed finding

- Settings and raw filter maps live above navigation; the panel does not keep a
  competing draft or save queue. Raw exit guards inspect current numeric nodes
  that need values, excluding removed views/nodes and irrelevant operators.
- Settings ACK acceptance removes only intents at or before the applied seq;
  later input is replayed over that exact accepted base. Unknown retains the
  operation and only resolve can resume the lane; the UI disables setting edits.
- New view and copied nested filter/sort identities are generated before intent
  submission and stay fixed across replay. Parent activeViewId drives read-only
  board/gallery/calendar rendering.
- Record raw number input remains App-owned and shared between table and record
  page. The displayed finite typed value can intentionally lag incomplete raw
  text; the raw field marks that state invalid and App blocks exit.

These are static observations, not a persistence or UI execution PASS. No heavy
test, dependency installation, build, or Electron launch ran in this lane.
