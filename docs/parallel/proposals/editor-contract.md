# Editor の文書属性と旧版互換についての統合提案

Editor branchは文書内の各ブロックおよび構造コンテナに `attrs.id` を追加する。既存の `Doc` 型・SQLite・保存IPC・revision契約は変更していない。IDは文書内で一意で、移動・Undo/Redoで保持し、コピーでは新規発行する。詳細と制限は `docs/parallel/editor/CONTRACT.md` を参照。

共通基準 `b7c150d` のvalidatorを試験したところ、旧文書は受け入れるが、ID付き文書は拒否する。これは旧版アプリ全体の復旧動作まで検証したことを意味しない。新コードが保存した文書は旧版でそのまま編集できるとは保証できない。

統合担当とDatabase担当への提案：共有の文書version・互換性方針、旧版で開いたときの原本保護、バックアップからの復旧、schema migrationと保存競合を、双方の実装に対する合同試験で確定する。versionを上げるだけで旧版が文書を読めるようになるわけではないため、旧版を許可する範囲と明示的な拒否・復旧手段を別途決める。現branchは他担当の共有型・store・DBを変更せず、合同統合試験は未実施。
