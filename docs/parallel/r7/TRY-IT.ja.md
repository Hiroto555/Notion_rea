# Folio R7 / W1を試す

この開発ビルドは最新統合済みR6 `02b83806d6d08b1b2c1b70a3a8f172466d8d658e` から作成したローカル版です。ブランチは `codex/folio-r7-integration`。クラウドや外部公開は含みません。

## 起動

Finderから `scripts/launch-r7.command` を開くか、ターミナルで実行します。

```sh
# リポジトリのルートで実行
node scripts/r7-demo.mjs
```

デモ専用データは `output/r7-demo/data`、生成内容の照合用manifestは `output/r7-demo/manifest.json` です。初回に合成データを作り、2回目以降は編集内容を残して開きます。既存のFolio workspaceを読み込む起動方法ではありません。現在このデモが開いている場合は、先にそのウィンドウを閉じてから再起動してください。

コードを変更した場合は、起動前に `npm run build` で再ビルドします。Viteサーバーを起動しなくても、生成済みの `dist/main.cjs` とrendererで動作します。

## 5〜10分の確認手順

1. サイドバーの「R7 制作タスク」を開く。「すべて」ビューには未完了の3行が表示されます。適用中のAND/OR条件、2つの並べ替えがツールバー下に表示されます。
2. 「フィルター」「並べ替え」「ビューのオプション」を開く。詳細を確認してEscapeで閉じる。「列の設定」には既存のpreview→適用の操作が残っています。
3. 「ステータス別」を開く。4件のカードで本文抜粋を読む。カードのタイトルからレコードを開き、本文を追記する。
4. 本文の一部を選択し、右上の全画面／サイドピーク切替を押す。本文・選択・Undoが同じEditorに残る。レコードを閉じると、開いたカードへフォーカスが戻ります。
5. 見積に `-` と入力して切替・遷移する。入力途中の文字は保持され、確定値として保存されません。最後に `6` などの数値へ完成させて保存を確認します。途中入力がある状態の終了・再読込は防がれ、理由が表示されます。
6. `⌘P` で「画面」を検索する。タイトル一致の「R7 画面を確認する」が上位になり、本文・プロパティ一致には該当箇所が表示されます。「要件」「合成」など日本語の短語でも試せます。
7. 通常ページ「R7 合成デモの使い方」を開き、ページメニューからMarkdownを書き出す。デモdataフォルダの外へ保存し、メニューから取り込む。タイトルと本文が戻り、自動生成タイトルのH1は本文に重複しません。一般のMarkdownに元からあるH1は保持されます。
8. 「保存済み」を確認しデモウィンドウを閉じ、同じ起動コマンドでもう一度開く。本文・値・ビュー設定の保持を確認します。

手順の時間は目安です。物理キーボードでの日本語変換は自動テストの代替ではなく、本人の環境で確認する項目です。

## 照合・回帰試験

```sh
npm run check
npm test
npm run build
npx playwright test
node scripts/verify-r7-workspace.mjs
```

最後のverifierは初期合成データとmanifestの完全照合です。デモを編集した後に不一致になるのは、その変更を検出した結果です。編集したデータを初期状態へ戻すコマンドではありません。

## 保持範囲と戻し方

Markdownはタイトルと対応する本文の入出力です。ページID・履歴・親子関係・添付を含む完全バックアップ復元ではありません。完全復元はW2以降の対象です。

元の 元の作業フォルダー のmaster、既存の未コミットファイル、実データは変更していません。R7デモを閉じれば元の環境へ戻れます。R6比較用ビルドは 別のR6比較用worktree に残しています。古いアプリをR7の編集データや実データへ向け直す操作は不要です。

デモを初期化したい場合は、アプリを閉じてから `output/r7-demo` 全体を別名で退避し、起動コマンドを再実行します。元データを消さずに新しい合成workspaceを生成できます。
