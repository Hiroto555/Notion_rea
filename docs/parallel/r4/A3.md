## Implemented UI contract

`ControlledRecordTable` accepts `databasePageId`, parent-provided `records` (with retained drafts overlaid), `properties`, `states`, `onPatch(pageId, patch)`, `onOpenRecord(pageId)`, and optional `onResolve(pageId)`. It does not copy these values to local state, create a save queue, send a revision, or offer an unconditional retry. Editing is enabled only when the parent explicitly sets that row's `editable: true`, and disabled for conflict/unknown/blocked/error states.

- Text, number and checkbox cells share the existing `PropertyField` with RecordPage. Title has a single parent command callback.
- Select/date values remain visible but disabled in the new table. Existing PropertyField callers retain support for these types.
- Pending/saving/saved/conflict/unknown/blocked/error are shown per row. The only recovery action offered is a callback to query an unknown operation's result.
- Row keys and `data-record-id` / `data-record-open-id` are stable page IDs. The scroll wrapper is marked `data-record-table-scroll` for the parent's scroll/focus restoration.
- Mismatched owners and duplicate page IDs render an error instead of writable controls.

DatabasePresentation's editable implementation contains component-local queues; this lane does not connect those queues to live persistence. The new table reuses its PropertyField and table styles. A0 can retain the existing read-only views beside this table; view settings persistence is not implemented here.

## Numeric drafts

PropertyField's optional `inputText` / `onInputTextChange` activates a parent-controlled text input for numbers. Every keystroke is sent to the parent raw draft; only a complete finite decimal/exponent value or deliberate empty input is also sent as a typed property command. Intermediate `-`, `.`, `1e-` and non-finite values are not converted to null.

ControlledRecordTable forwards `inputTexts[pageId][propertyId]` and `onInputTextChange(pageId, propertyId, text)`. A2 adds the corresponding RecordPage props. A0 owns this map across navigation and uses `parsePropertyNumberInput` to block normal exit/reload while an incomplete draft remains. The raw draft is not durable across process crashes. If no raw-text callback is supplied, PropertyField keeps its existing native number-input behaviour for compatibility.
