# R4 A1 保存コア

## 接続口

- `SaveOperation` は operationId、sessionId、seq、pageId、固定 owner（通常 Page は null）、表示 base revision、Page patch、任意の property values を含む。
- `save:commit` は Page と values、履歴、SHA-256 fingerprint と適用 receipt を一つの SQLite transaction で確定する。record の本文・title・values は 1 revision 進む。title は Page のみが正本。
- 同 ID・同 payload は保存済み結果を返し、revision と履歴を増やさない。同 ID・異なる payload は拒否する。入力不適合・競合による業務拒否は savepoint rollback 後の terminal receipt として保持する。
- `save:resolve` は元 operation 全体を要求する。receipt がない場合は unknown を返す。未着の元要求が後で実行される可能性があるため、不在を未適用・再送許可へ読み替えない。
- Store 呼出しは main の同一 event loop 上で同期実行される。commit/resolve の業務処理途中に await はない。通信より前の未到着要求も考慮し、不在は常に unknown。

`sendReliableSave(operation)` / `resolveReliableSave(operation)` は 15 秒で unknown にする。通信例外と ACK の identity・fingerprint・内容不一致も unknown。自動再送・自動照会は行わない。

## record の session

`EditSessionCoordinator` は App 寿命で保持する。既存の 1000 行の試作 coordinator は互換性のため維持し、読取 snapshot の validator を再利用した。

- `attach(page, record?)` → `{pageId,sessionId}`。再 attach や list refresh では既存 session を置き換えない。
- `get(pageId)` → `{handle,page,record,state,error,seq,baseRevision,operation}`。page/record は ACK base と未保存 intent の overlay。
- `edit(handle,patch,values?)` は seq を増やして保持する。保存は開始しない。
- `flush(pageId)` は同じ lane の送信を直列化。遅延 ACK はその operation の seq までだけ確定し、追加入力を保持する。
- `resolve(pageId)` は unknown を照会し、applied が確認できた場合だけ後続 intent の保存へ進む。
- `subscribe(callback)` / `views()` / `hasUnsaved()` を App の表示・離脱制御で利用する。
- flush/resolve の通信・保存エラーは state に格納し、拒否 Promise にしない。無効 handle の edit、初期 snapshot 不正の attach は同期例外。

state は saved / pending / saving / conflict / unknown / blocked。conflict/unknown 中も追加入力を保持するが後続 write は停止する。UI の open/close/full 切替はこの session を破棄しない。

## R4 の境界

- 通常 Page は既存 PendingEdits/global queue/journal を A0 が維持し、同じ receipt API に接続する。通常 Page の表示 base と履歴復元 lock は A0 の担当。
- record・登録済み DB の履歴復元は main IPC で拒否する。Store 内の未接続 prototype の履歴 API と既存 unit は保存している。
- record/登録 DB の move は既存 Store の拒否を継続。起動時の旧 rows → record 自動変換は追加していない。
- receipt は再起動後も照会できる。ただし renderer の未解決 operation/draft はメモリ保持で、durable outbox は実装していない。通常終了・再読込を A0 が抑止する。強制終了・OS crash 後の draft 自動復旧や完全 backup は提供しない。
- 外部任意 SQLite writer/旧 binary 排除、所属 A→B→A 世代検知、receipt の保持期限・肥大化対策は対象外。
