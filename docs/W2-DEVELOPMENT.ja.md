# Folio W2 開発版

W1完成版 `bf3a68b58f41739750e8c8d1a067c3588cede8f9` を基点にした、ローカル専用の開発版です。

## 起動

```sh
# リポジトリのルートで実行
npm run build
./scripts/launch-r8.command
```

初回は `output/r8-demo/data` に専用の合成データを作ります。次回は同じデータを開きます。既存のW1デモ、元の作業フォルダー、通常利用のFolioデータには接続しません。

## 試す操作

- ページメニュー → **バックアップと復元** → **バックアップを作成**。件数・容量・保存先を確認できます。
- **バックアップを選んで検証**で、この版で作成した完全バックアップを選べます。
- **新しいフォルダーへ復元**では親フォルダーを選びます。新規の `Folio-restored-*` フォルダーを作り、既存のフォルダーを上書きしません。
- **復元先を開く**で、この開発版の別プロセスが起動します。元のアプリは開いたままです。
- 右の「ページの情報」には、リンク元の本文文脈と一致部分が表示されます。文脈を押すとリンク元のブロックへ移動します。レコードでは本文の下に表示します。
- 「ページの幅」の **標準／ワイド** を切り替えます。通常ページとDBは情報パネル、レコードは本文の上にあります。表示切替は同じエディターと入力状態を維持します。

## 保存と復元の範囲

完全バックアップは、保存済みのSQLiteスナップショット・添付ファイル・検証用manifestを含みます。ページ／レコードのID・本文・値・ビュー・設定・履歴・保存操作の結果記録を保持します。SQLite整合性、関係、内容のハッシュ、添付のサイズとハッシュを照合します。

未保存・競合・保存結果不明・入力途中の数値が残る場合、画面からのバックアップ作成を止め、入力を保持します。未保存入力の復旧は従来の復旧記録が担当し、完全バックアップには一時的な編集セッションを混ぜません。

復元途中の出力には `FOLIO-RECOVERY-INCOMPLETE` を残します。このマーカーがある保存先は通常起動を拒否します。失敗した出力を自動削除したり、元のデータへ書き戻したりしません。

各プロセスで最初に幅を保存する直前に、`backups/before-page-layout-*` へ検証済みバックアップを作ります。バックアップに失敗した場合、幅の保存を止め、既存の保存・再試行契約に従います。

## 互換性

幅が未指定のページは従来通り、通常ページ／レコードが標準、DBがワイドです。起動時に既存行を一括更新せず、SQLiteのバージョンも変更しません。

幅を含むページ退避JSONには `folio-page-recovery` v3、実験用の混合ポータブル退避にはv5を使います。旧形式の読込みは維持します。旧アプリで新形式を読み込ませて幅を黙って失うことを避けるため、形式を区別します。完全バックアップ復元はポータブル退避とは別経路で、IDを付け替えません。

この版で編集したデータを古いビルドに直接渡さず、必要なら変更前バックアップを別の保存先へ復元してください。元のW1作業ツリーと専用データは残しています。

## 検証

```sh
npm run check
npm test
npm run build
npx playwright test
```

W2受け入れ試験は `tests/e2e/r8-acceptance/`。すべて専用の合成データで行います。性能計測も `scripts/r8-performance.mjs` で専用データに対して行い、物理的なコールドキャッシュや実IME試験とは区別します。最終結果・画面・未確認事項は別の実行レポートを参照してください。
